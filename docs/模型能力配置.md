# 模型能力配置指南

DSH 里"某个模型能不能读图""子代理能用哪些模型"，**取决于配置声明，而不是模型自动识别**。配置里缺一行声明，就会出现"明明支持的模型却用不了"。本文记录如何查看、如何声明、以及常见报错的对照处理。

---

## 一、怎么查看当前模型能力

### 方法：用 `llm` 服务探测

挂载一个临时 Cordis 插件（或让 agent 用 `cordis_define` 定义一个），注入 `llm` 服务后查询：

```js
// 列出所有 provider 的模型
for (const p of ctx.llm.listProviders()) {
  const models = await ctx.llm.listModels(p.id || p.name)
  for (const m of models) {
    const info = await ctx.llm.resolveModelInfo(p.id || p.name, m.id || m.name)
    console.log(p.id, m.id, info.inputModalities)   // ['text'] 或 ['text','image']
  }
}
```

`info.inputModalities` 含 `image` 才**能**读图。

## 二、图像能力声明（重点，最容易踩的坑）

### 关键事实

DSH 的模型能力字段 **默认值是 `["text"]`**：

```js
inputModalities: model.inputModalities ?? ["text"]
```

也就是说——**即使模型实际支持图像，只要配置里没声明 `image`，`read_image` 就会被拒绝**：

```
Error: cannot read "xxx.png" as an image:
model "xxx" does not declare image input;
switch to an image-capable model to read images
```

### 怎么声明

在 `~/.dsh/settings.yaml` 对应 provider 的模型条目下补 `inputModalities`：

```yaml
llm-deepseek:
  models:
    - id: deepseek-flash
      name: DeepSeek-V4.1-Flash
      inputModalities:
        - text
        - image        # ← 补上这行，就能读图了
```

> 配置是**热加载**的，通常不需要重启 DSH。

### 可选图像参数

声明 `image` 后，还可以细调图像处理预算（都以适配器默认值为准，可不填）：

```yaml
      inputModalities:
        - text
        - image
      imagePixelBudget: low      # 像素预算：数字，或 "low"（低精度）
      imageMaxBytes: 1048576     # 单图编码字节上限
```

### schema 约束（配错会报错）

- `inputModalities` 只能含 `"text"` / `"image"`，**不能为空、不能重复**；
- **text-only 模型不能声明 `imagePixelBudget` / `imageMaxBytes`**（会报错提示）。

## 三、子代理模型白名单

DSH 可以限制"子代理能用哪些模型"，配置在 `settings.yaml`：

```yaml
subagent-model-selection:
  enabled: true
  allowedModels:
    - provider: deepseek-official
      model: deepseek-flash
    - provider: kimi-coding
      model: k3-256k
    - provider: kimi-coding
      model: kimi-for-coding
```

**要点**：
- `workflow` / `subagent` 派生子代理时，**指定白名单外的模型会失败**（子代理返回 `null`）；
- 规划"识图 / 审查"用哪个模型前，先确认它在白名单里，或把目标模型加进白名单。

## 四、常见报错对照表

| 报错 / 现象 | 原因 | 处理 |
|---|---|---|
| `model "X" does not declare image input` | 配置缺 `image` 声明（默认 `["text"]`） | 在该模型配置里加 `inputModalities: [text, image]` |
| `The DeepSeek chat-completions adapter does not support image content` | 请求走了 text-only 路径 | 同上：补图像声明 |
| 子代理返回 `null` / 无输出 | 指定了**白名单外**的模型 | 换成 `allowedModels` 里的模型，或把目标模型加进白名单 |
| 预设挂载失败：`$.prefix missing required value (at prefix)` | DSH 升级后 `dsh-persona` 字段由 `text` 改为 `prefix` | 把 `agent.cordis.yml` 里 persona 的 `text:` 改成 `prefix:` |
| `row(s) published process-global service(s) [...]` | 预设里有行发布了服务但没放在 `isolate` realm 里 | 用 `cordis:group` + `isolate` 包住该行 |

## 五、实测案例（2026-09-10）

**现象**：用 DeepSeek V4.1 Flash（`deepseek-official/deepseek-flash`）读图，`read_image` 报 `does not declare image input`。

**排查**：
1. `llm.resolveModelInfo` 显示 `inputModalities = ["text"]`；
2. 查 `dsh-llm-deepseek` 源码，发现适配器**本身支持图像**（`prepareRequestImages`、`resolveRequestImagePolicy`、v4 vision token 计费、PNG/JPEG/WebP/GIF 支持），且内置模型目录里 `deepseek-v4-flash` 声明的是 `["text", "image"]`；
3. 根因：`settings.yaml` 里自定义的那条 `deepseek-flash` 条目**漏了图像声明**。

**修复**：补上 `inputModalities: [text, image]`。

**验证**：修复后实测 V4.1 Flash 成功读图，并输出完整的逐项审查（标题 / 坐标轴 / 图例 / 遮挡 / 几何自洽 / PASS 判定）。

---

## 六、经验小结

1. **"能不能读图"看配置声明，不看模型名气**——先 `resolveModelInfo` 确认，别凭印象判断；
2. **实际支持图像却被拒**，第一反应应该是"配置里有没有声明 `image`"；
3. **派子代理前先看白名单**，避免白跑一轮；
4. **DSH 升级后留意 schema 变化**（如 `text` → `prefix`），升级后跑一次预设挂载校验（`agentPresets.standingKeyFor(id)`）能及早发现。
